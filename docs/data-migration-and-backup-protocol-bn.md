# ডেটা মাইগ্রেশন, ব্যাকআপ ও জিরো-ডেটা-লস প্রোটোকল

Money Tracker (আমার হিসাব) অ্যাপ্লিকেশনের প্রোডাকশন কাটওভার ও ডাটাবেস মাইগ্রেশনের সময় ডেটা অক্ষত ও নিরাপদ রাখার বিস্তারিত প্রোটোকল নিচে দেওয়া হলো।

---

## ১. ব্যবহারকারীর ডেটা এক্সপোর্ট পদ্ধতি

যেকোনো সার্ভার বা ডাটাবেস পরিবর্তনের পূর্বে ইউজার তার নিজস্ব ডেটা এক্সপোর্ট করে রাখবেন:

1. অ্যাপ্লিকেশনের সাইডবার থেকে **"ব্যাকআপ ও রিস্টোর" (Finance Backup)** অপশনে যান।
2. **"সম্পূর্ণ ডেটা এক্সপোর্ট করুন"** বাটনে ক্লিক করুন।
3. সিস্টেমে সংরক্ষিত সমস্ত প্রজেক্ট, ক্যাটাগরি, লেনদেন, ঋণ-পাওনা এবং ভাউচার সেটিংস একটি স্ট্যান্ডার্ড `money_tracker_backup_*.json` ফাইলে ডাউনলোড হবে।
4. এক্সপোর্ট ফাইলের ফরম্যাট:
   ```json
   {
     "version": "1.0",
     "exportedAt": "2026-08-28T...",
     "user": { "id": "...", "email": "..." },
     "projects": [...],
     "transactions": [...],
     "accounts": [...],
     "categories": [...],
     "dues": [...],
     "budgets": [...]
   }
   ```

## ২. নিরাপদ কাটওভার ও রিস্টোর প্রোটোকল (Zero-Data-Loss)

1. **স্টেজিং টেস্ট:** প্রথমে একটি ডামি/ব্ল্যাংক প্রোফাইলে এক্সপোর্ট ফাইল আপলোড করে প্রিভিউ ও রিস্টোর টেস্ট সম্পন্ন করা হবে।
2. **প্রোডাকশন অনুমোদন:** ইউজার ব্যাকআপ নিশ্চিত করার পর নতুন ডাটাবেস সংযোগে মাইগ্রেশন স্কিমা রান করা হবে (`pnpm db:push`)।
3. **ইউজার রিস্টোর:** নতুন সিস্টেমে লগইন করে এক্সপোর্ট ফাইলটি আপলোড করলে সম্পূর্ণ ডেটা নতুন প্রজেক্ট হিসেবে কোনো পূর্ববর্তী ডেটা ওভাররাইট না করে নিরাপদে রিস্টোর হবে।
4. **রোলব্যাক ব্যাকআপ:** যেকোনো ত্রুটি দেখা দিলে পূর্বের লাইভ হোস্টিং ও ডাটাবেস অক্ষত থাকায় অবিলম্বে পুরনো সিস্টেমে ফিরে যাওয়া সম্ভব।
